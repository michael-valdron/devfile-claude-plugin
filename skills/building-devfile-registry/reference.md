# Devfile Registry Reference

## Stack directory patterns

### Single-version stack

```
stacks/my-stack/
└── devfile.yaml
```

### Multi-version stack

```
stacks/my-stack/
├── stack.yaml
├── 1.0.0/
│   └── devfile.yaml
└── 2.0.0/
    ├── devfile.yaml
    └── docker/
        └── Dockerfile
```

Non-devfile files in a version directory are tar-archived as `archive.tar` during build (see `build-tools/build.sh` `tar_files_and_cleanup`).

## devfile.yaml metadata requirements

Key fields consumed by the index generator:

| Field | Source |
|-------|--------|
| `metadata.name` | Stack name; must match directory / `stack.yaml` |
| `metadata.version` | Version; must match version directory |
| `schemaVersion` | Devfile API version |
| `metadata.displayName`, `description`, `icon` | Shown in registry viewer |
| `metadata.tags`, `projectType`, `language` | Filtering |
| `starterProjects` | Listed in index |
| `commands[].group.kind` | Populates `commandGroups` in index |

Example: `tests/registry/stacks/go/1.2.0/devfile.yaml`

## extraDevfileEntries.yaml

Root-level file for external samples not stored under `stacks/`. Each sample entry includes Git remote URLs that `cache_samples.sh` clones at build time.

Schema version at top level: `schemaVersion: 1.0.0`

Example fields per sample:

```yaml
samples:
  - name: nodejs-basic
    displayName: Basic Node.js
    description: A simple Hello World Node.js application
    projectType: nodejs
    language: nodejs
    versions:
      - version: 1.1.0
        schemaVersion: 2.2.0
        default: true
        git:
          remotes:
            origin: https://github.com/example/devfile-sample.git
```

See `tests/registry/extraDevfileEntries.yaml` for working examples.

## index.json

Generated by `index/generator/index-generator` from stacks + `extraDevfileEntries.yaml`. Schema defined in `index/generator/schema/schema.go`. Each entry has `type: stack` or `type: sample` with a `versions[]` array.

Sample index entry fields: `name`, `displayName`, `description`, `type`, `tags`, `architectures`, `projectType`, `language`, `lastModified`, `versions[]`.

Each version includes: `version`, `schemaVersion`, `default`, `links.self`, `resources`, `starterProjects`, `commandGroups`, `lastModified`.

## Build pipeline (build-tools/build.sh)

1. Copy registry repo to output dir
2. Build index-generator
3. Tar-archive ancillary files per stack version
4. Cache external samples (`cache_samples.sh`) if `extraDevfileEntries.yaml` exists
5. Run `index-generator <registry-dir> <output>/index.json`

## Container image layers

Final index image = `devfile-index-base` + `/registry` (stacks + index.json). See `build-tools/Dockerfile` and `.ci/Dockerfile`.

## Offline builds

Pass `1` as the second argument to `build_image.sh` to download parent devfiles and starter projects for air-gapped use:

```bash
bash build-tools/build_image.sh <path-to-registry-repo> 1
```

This runs `dl_parent_devfiles.sh`, `dl_starter_projects.sh`, and `update_devfiles_offline.sh` before the standard build.
